# Shop-Picker — Data Sync Pipeline

This folder contains the automated pipeline that keeps the `product_test` table in Supabase up to date every 24 hours.

---

## What the pipeline does

Every day the script `sync_data.py` runs through five steps in order:

```
[1] Download latest ZIP from kolkostruva.bg
        ↓
[2] Import all CSV files → product_test (truncate first)
        ↓
[3] Deduplicate rows (same product + city + price → keep one)
        ↓
[4] Clean product names + extract measurements
        ↓
[5] Extract brand names
```

### Step 1 — Download
Downloads the open-data ZIP published daily at `https://www.kolkostruva.bg/opendata_files/<YYYY-MM-DD>.zip`.
If today's file is not yet available it tries yesterday's. The previous `data/stores/` folder is backed up to `data/backup/` before extraction.

### Step 2 — Import
Truncates `product_test`, then bulk-inserts every `.csv` file found in `data/stores/` in batches of 10 000 rows.
Each CSV uses `;` or `,` as delimiter — detected automatically.
Columns imported: `city`, `store`, `product_name`, `code`, `category`, `price`, `price_promotion`.

### Step 3 — Deduplicate
Removes rows where the same product code is sold at the same price in the same city. Each chain (Billa, Kaufland, etc.) has the same price across all its branches in a city, so keeping every branch row creates massive duplicates with no extra information.

Dedup key: `(code, city, price, price_promotion)`
Typical reduction: ~1 700 000 rows → ~770 000 rows (~55% smaller).

### Step 4 — Clean product names & extract measurements
Calls the PostgreSQL function `clean_product_name()` on every row to strip measurements, `#` markers, leading numeric codes, container words, and orphan punctuation.
Calls `extract_measurement()` to populate the `measurements` column (e.g. `"100г"`, `"1.5л"`, `"800г / 530г"`).

### Step 5 — Extract brand names
Calls `extract_brand()` on every cleaned product name and stores the result in the `brand` column.
The function uses a 3-pass strategy:
1. Skip leading Bulgarian category / descriptor words
2. Collect 1–2 consecutive Latin brand tokens
3. Fallback to first Latin non-descriptor word anywhere in the name
4. Fallback to first Cyrillic non-descriptor token

## One-time database setup (required before first run)

The pipeline calls PostgreSQL functions that must already exist in the database. Run the following sections of `shop_picker_scripts.sql` **once** in the Supabase SQL editor before using this pipeline:

### Section 1 — Create the table
```sql
CREATE TABLE IF NOT EXISTS public.product_test (
  id               bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  category         varchar,
  city             varchar,
  code             varchar,
  product_name     varchar,
  price            varchar,
  price_promotion  varchar,
  store            varchar,
  brand            text,
  measurements     text
);
```

### Section 2 — Helper: `is_product_type_word(text)`
Returns `TRUE` if a Bulgarian word is a category/descriptor that should never be treated as a brand name (e.g. "КИСЕЛО", "ЧАЙ", "ШАМПОАН").
**Run the full `CREATE OR REPLACE FUNCTION` block from the SQL file.**

### Section 3 — Helper: `is_latin_descriptor(text)`
Returns `TRUE` if a Latin word is a generic descriptor/adjective (e.g. `ORGANIC`, `CLASSIC`, `BLUE`).
**Run the full `CREATE OR REPLACE FUNCTION` block from the SQL file.**

### Section 4 — Function: `extract_measurement(text)`
Extracts the size/weight token from a raw product name.
Examples: `"Milka шоколад 100гр"` → `"100гр"`, `"1.5Л ВОДА"` → `"1.5Л"`.
**Run the full `CREATE OR REPLACE FUNCTION` block from the SQL file.**

### Section 5 — Function: `clean_product_name(text)`
Strips measurements, `#` markers, leading numeric codes, container words (`БУТИЛКА`, `КУТИЯ`, etc.) and orphan punctuation.
Examples:
- `"#OGX Шампоан Keratin oil 385ml"` → `"OGX Шампоан Keratin oil"`
- `"Lindt Classic млечен шоколад 100гр"` → `"Lindt Classic млечен шоколад"`

**Run the full `CREATE OR REPLACE FUNCTION` block from the SQL file.**

### Section 6 — Function: `extract_brand(text)`
Extracts the brand name using the 3-pass strategy described above.
Examples:
- `"Colgate Паста Max White"` → `"Colgate"`
- `"VICHY DERCOS Шампоан"` → `"VICHY DERCOS"`
- `"КИСЕЛО МЛЯКО БИАНКИНА"` → `"БИАНКИНА"`

**Run the full `CREATE OR REPLACE FUNCTION` block from the SQL file.**

> Sections 7 (procedure) and 10 (useful queries) are optional — they are not required for the automated pipeline.

## Environment variables

Copy `.env.example` to `.env` and fill in your values:

```env
SPRING_DATASOURCE_URL=jdbc:postgresql://<your-supabase-host>:5432/postgres
SPRING_DATASOURCE_USERNAME=postgres
SPRING_DATASOURCE_PASSWORD=<your-supabase-db-password>
```

The URL must stay in JDBC format — the script converts it to a standard PostgreSQL URL internally.

For the GitHub Actions workflow, add the same three values as repository secrets under:
**Settings → Secrets and variables → Actions**

## Automated scheduling (GitHub Actions)

The workflow file [`.github/workflows/sync-data.yml`](../../.github/workflows/sync-data.yml) triggers this pipeline automatically:

- **Scheduled**: every day at **03:00 UTC**
- **Manual**: trigger from the *Actions* tab in GitHub at any time

The workflow:
1. Checks out the repository
2. Installs Python 3.12 and the packages from `requirements.txt`
3. Writes `.env` from GitHub Actions secrets
4. Runs `python sync_data.py`

The job has a 120-minute timeout. On a Supabase free tier with ~750k rows after dedup, expect the full run to take 30–60 minutes.

## Useful queries (run manually in Supabase)

**Check pipeline results after a run:**
```sql
SELECT
  COUNT(*)                     AS total_rows,
  COUNT(brand)                 AS has_brand,
  COUNT(measurements)          AS has_measurements,
  COUNT(DISTINCT brand)        AS distinct_brands,
  COUNT(DISTINCT city)         AS distinct_cities
FROM product_test;
```

**Spot-check cleaned names:**
```sql
SELECT product_name, brand, measurements
FROM product_test
WHERE product_name IS NOT NULL
ORDER BY RANDOM()
LIMIT 50;
```

**Most common brands:**
```sql
SELECT brand, COUNT(*) AS cnt
FROM product_test
WHERE brand IS NOT NULL
GROUP BY brand
ORDER BY cnt DESC
LIMIT 50;
```

**Verify no duplicates remain:**
```sql
SELECT
  COUNT(*)                                             AS total_rows,
  COUNT(DISTINCT (code, city, price, price_promotion)) AS unique_combinations
FROM product_test;
-- total_rows should equal unique_combinations
```

**Brands that look suspicious (too short — possible cleaning issue):**
```sql
SELECT product_name, brand
FROM product_test
WHERE brand IS NOT NULL
  AND length(brand) <= 3
ORDER BY RANDOM()
LIMIT 30;
```
